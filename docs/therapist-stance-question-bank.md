# Therapist stance question bank

The exercise uses 60 committed, authored scenarios. The original q01–q15
remain unchanged; q16–q60 provide three alternatives per original scoring slot.
No scored question or option is generated by runtime AI.

An attempt selects one question for each of the 15 pairs of the six existing
dimensions. Each dimension therefore has five contributing items, capacity 10,
with the original four combinations of ±2 weights. Context responses count for
completion and remain missing scoring evidence. Thresholds and interpretations
are unchanged. This preserves editorial scoring, without claiming psychometric
equivalence of different scenario wording.

Selection prefers unseen questions within each slot. When a slot is exhausted,
it reuses its least recently seen question. Randomness only resolves selection
ties. Four attempts from an empty history cover the whole bank without repeats.
The selection stays fixed while answering, reviewing, and writing a report.

Seen history contains IDs only, scoped to the authenticated therapist in browser
storage. All 15 questions are recorded as presented when an attempt starts,
including attempts later abandoned. Saved reflection snapshots supply history
across browsers; legacy snapshots supply their response keys. Unsaved attempts
from another browser are unavailable. Blocked storage uses in-memory history;
failed saved-history reads show a notice and preserve quiz availability.
No responses are automatically persisted.

Replacing an active attempt requires confirmation. An unsaved result also warns
before replacement; a saved result can start another reflection directly. A new
attempt clears answers and report state while leaving saved records intact.

New bank snapshots use `cpd-stance-snapshot-v3`, question version
`therapist-style-bank-v2-draft1`, and ordered `questionIds`. The original scoring
version is retained. The optional narrative endpoint validates the IDs and pair
balance and recomputes scores from authored weights before calling AI.

Snapshots v1 and v2 without question IDs continue through the original 15-item
scoring path and retain their exact saved representations and text exports.
Changes to released text or weights require a new bank version and preservation
of the old resolver; never edit released IDs to mean different questions.

Verification:

```powershell
node --test test/unit/stance-question-bank.test.js test/unit/practice-reflection.test.js test/unit/practice-reflection-presentation.test.js test/therapeutic-stance-ai.test.js
node node_modules/@playwright/test/cli.js test --config playwright.stance.config.js
npm run build
```

Browser QA uses an isolated localhost server, fictional authentication and mocked
services at desktop 1440×1000 and mobile 390×844. It covers cancellation and
confirmation, answer reset, unseen preference, history reload, saved source IDs,
optional AI request IDs, history failure, layout width, and heading clearance.
Screenshots and failure traces go to `test-results/stance`.
